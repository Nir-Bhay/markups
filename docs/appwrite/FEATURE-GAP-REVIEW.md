## Suggested order

1. Fix note-scoped history and media portability; define stable IDs and account boundaries. These benefit the current editor independently of a backend.
2. Add optional identity and foreground provider Save/Open. Documents can stay in the user's Drive/GitHub, reducing Markup storage commitments.
3. Add a small private-backup pilot for selected text notes with server quotas. Detect unresolved local media and offer a portable alternative or explicitly labelled text-only action; never claim an incomplete backup is complete.
4. Add automatic sync, bounded cloud history, revocable shares and preference sync only after their proof gates.

Public upload galleries, remote AI chat, realtime collaboration and compute-heavy exports should not enter the first backend release by default.

## Capability boundaries

Appwrite does not fix Monaco/Markdown/Mermaid memory usage or browser PDF limits. Google/GitHub still own their file permissions. Login does not grant document-upload consent. ACLs/encryption do not imply end-to-end encryption. Deleting an Auth account is not an automatic cascade across every application row, file, share and provider token. Database transactions do not include Storage uploads or provider writes.

No OAuth application was registered, no user Drive/repository authorized, and no cloud document saved. No Appwrite project, tables or functions were created. Provider/token failure POCs, real quota races, ACLs and runtime privacy checks remain outstanding. Local automated tests do not substitute for these live-service checks.
