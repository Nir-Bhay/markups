# Markups SEO and editorial audit — 2026-11-04

## Executive summary

This audit covers the Markups source build, the current public `markups.dev` deployment, the connected Google Analytics 4 and Search Console properties, and the `claude-seo` toolkit (v2.5.0). The new editorial pages build cleanly in the workspace. They are **not deployed**.

The highest-priority finding is a release mismatch: the live sitemap currently contains 10 URLs, while the source sitemap contains 23. Of the 23 source sitemap URLs checked against production, 11 returned HTTP 200 and **12 returned HTTP 404**. Four missing routes are privacy/terms/cookie/accessibility pages; `/seo/compatibility-lab` is also missing; the new Markdown guide, blog index and five articles are not live. Do not submit the new URLs to Search Console or describe them as published until a reviewed deployment includes them.

Search demand is not yet large enough for reliable keyword-volume claims. Search Console reported 91 impressions and 2 clicks for the 90-day window, and only 6 impressions with no clicks in the last 28 days. GA4 recorded 56 organic-search sessions in the 90-day window, but these remain small samples. Ahrefs' keyword endpoint returned `Insufficient plan`, and Search Console query coverage is limited; this report gives intent clusters and observed queries, not invented search volumes or traffic forecasts.

## Scope and method

- **Audit date:** 2026-11-04 (Asia/Kolkata). Search Console and Analytics data were queried through the connected Windsor account for the most recent complete ranges available at the time; ranges and limits are shown below.
- **Repository:** current workspace source under `markups/`; no production files, settings, DNS, analytics configuration, or deployment were changed.
- **Analytics:** Windsor read-only Google Search Console property `https://markups.dev/` and GA4 host-filtered to `markups.dev`. Personal account identifiers and raw user-level data are intentionally omitted.
- **Live crawl:** read `robots.txt` and the declared sitemap; fetched all 10 live sitemap URLs for status/title/canonical/robots and tested every URL in the 23-URL source sitemap against production.
- **Local checks:** Vite production build, repository SEO static audit, built-site audit, built-page artifact check, whitespace check, and the isolated `claude-seo` scripts noted below.
- **Out of scope/unavailable:** authenticated Vercel preview, Search Console URL Inspection/indexing reasons, Bing Webmaster, backlink databases, full browser/Lighthouse/CrUX performance results, production deployment, and AI-search citation experiments. Ahrefs keyword-data access was checked and returned `Insufficient plan`; no keyword metrics were returned.

The connected analytics sample is useful for prioritizing follow-up, not for establishing causality or predicting rankings. Search Console suppresses anonymized queries; the query table is not a complete keyword list. No composite SEO score is reported because indexing, authority/backlinks, performance field data, and full browser crawl evidence are incomplete.

## Technical SEO and live-vs-source audit

### Live production snapshot

- `https://markups.dev/robots.txt` returned successfully and declared `https://markups.dev/sitemap.xml`.
- The `claude-seo` sitemap discovery script fetched the declared live sitemap with HTTP 200 and parsed a valid URL set. The public sitemap had **10 URLs** at audit time.
- All 10 live-sitemap pages returned HTTP 200. Title, robots and canonical metadata were read for those pages; the root page has a self-canonical and `index, follow`.
- Of the 23 URLs in the current source sitemap, **11 returned HTTP 200 and 12 returned HTTP 404** when fetched from production: `/privacy-policy`, `/terms`, `/cookie-policy`, `/accessibility`, `/seo/compatibility-lab`, `/markdown-guide`, `/blog`, and the five new blog-post URLs. This is a production-release/indexing issue, not a failure of the local Vite build.
- The local source sitemap lists 23 URLs; root and public sitemap XML are identical. It is valid source for a release containing the current route set, but it does not describe current production until deployment.
- The current live sitemap does not yet include `/landing` even though that route currently returns HTTP 200 and the source sitemap includes it. Resolve the live sitemap/source mismatch through the normal reviewed release flow.
