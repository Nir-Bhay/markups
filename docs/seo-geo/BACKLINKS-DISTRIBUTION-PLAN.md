# Markups backlinks and discovery plan

Prepared 2026-11-04. This is a research/action plan, not proof that any listed site currently links to Markups. No outreach, posting, paid placement or external account write was performed.

## Prerequisite

First deploy the reviewed content and fix live 404s. Inspect the exact destination URL, mobile presentation and product claims before asking anyone to link. Current live sitemap/source mismatch is the first blocker. A good referral landing page should solve the linked problem immediately, with an optional path to the editor.

## Where to earn relevant links

| Opportunity | Destination asset | Concrete action | Verification |
|---|---|---|---|
| Existing repository/profile links | Canonical product tour/editor | Review own GitHub repository About URL, README and accurate owner profiles; replace obsolete domain references where authorized | Public page contains intended URL; redirect works |
| Existing third-party listings | Canonical destination | Recheck Awesome Markdown Editors, LibHunt and earlier listing findings; ask maintainers to correct the old domain with evidence | Inspect live listing and final target; historical observations alone are not current proof |
| Developer documentation resources | Compatibility Lab and downloadable fixtures | Produce a useful, tested example and suggest it only where the resource's inclusion policy fits | Maintainer independently accepts; record actual link |
| Technical problem discussions | Exact troubleshooting article | Answer the problem fully in the discussion; disclose relationship when sharing own relevant resource; follow community rules | Helpful response exists; record referral engagement if measurable |
| Independent technical writing | Original tested workflow/fixture | Write a distinct explanation for an appropriate publication, cite sources and disclose Markups involvement | Editorial acceptance and real reader value; no guaranteed link |
| Markdown learning resources | Guide or narrow syntax example | Offer a specific correction or missing example instead of a generic “add my tool” request | Accepted editorial change, accurate attribution |
| Open-source collaboration | Useful code/documentation contribution | Fix a real issue in an ecosystem project; include a resource only when technically relevant and permitted | Contribution accepted on its merits; no link requirement |

AlternativeTo, SaaSHub, Product Hunt and similar discovery channels require separate eligibility/rules checks. A profile link may be nofollow and still deliver relevant users. Do not sell a DR score or a dofollow-link quota as a growth strategy.

## Create assets worth referencing

Prioritize the existing compatibility fixture: same input, named renderer/version, expected outputs, screenshots and reproducible limitations. Then add a downloadable troubleshooting pack: newline variants, image-folder example, nested-list cases and code fences. Each should have a stable public page and actual files. No competitor benchmark without equivalent independently checked conditions. These assets support the existing articles and avoid another layer of generic SEO copy.

## Outreach workflow for the owner

1. Identify a specific resource or discussion and read its rules; record the exact relevant gap.
2. Verify the destination asset and prepare an explanation of why it helps those readers.
3. Send a personalized suggestion only after choosing the recipient/channel and authorizing the send. No automatic bulk messaging or invented endorsement.
4. Follow up only when appropriate; respect declines. Acceptance is the editor's decision.
5. Record the real resulting link and referrer traffic, not a promised placement.

Use branded, URL or descriptive natural anchors chosen by the publisher. Avoid buying ranking links, automated directory blasts, reciprocal-link networks and exact-match spam. Google's policy distinguishes legitimate promotion from links primarily made to manipulate ranking. [Google link-spam policy](https://developers.google.com/search/docs/essentials/spam-policies).

## Tracking sheet

Use `runs/2026-11-04-search-readiness/BACKLINK-OPPORTUNITIES.csv`. Initial rows are research targets, **not verified backlinks**. Fields: source URL, audience/relevance, target URL, gap, rules checked, contact permission, date, status, resulting link, rel attribute if visible, final target status, referral sessions, qualified activation and notes. Keep personal contact details outside this public repository.

Campaign UTMs may be used for owner-controlled campaign links where permitted; use the app's allowlisted `utm_source`, `utm_medium`, `utm_campaign` with simple safe values, e.g. `utm_source=dev_resource&utm_medium=referral&utm_campaign=markdown_fixture`. Avoid UTMs on normal internal links and canonical URLs. Do not modify another publisher's chosen URL just to force attribution.

## How to measure progress

- Leading indicators: useful assets completed, relevant personalized suggestions made by the owner, accepted corrections and live referring pages.
- Outcomes: qualified referral visits, editor starts and export completions after measurement is actually available.
- GSC Links report is a sample/delayed view, not a full real-time backlink database. A link's absence there does not prove it does not exist.
- Review broken/obsolete destinations monthly. Use permanent redirects for genuine moved pages and update owned links.
- Do not infer Google indexing, rankings or AI citations from backlink counts. No paid backlink database was queried successfully in this run.

For search and answer engines, accurate source identity, clear canonical content and genuinely useful references matter more than a checklist of artificial placements. [Bing link/discovery guidance](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a).
